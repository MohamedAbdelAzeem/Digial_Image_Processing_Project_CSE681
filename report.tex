\section{Dataset and Baseline Plan}

The Kodak image dataset is used as the common evaluation dataset for
the compression methods in this project. It contains 24 test images,
each with a resolution of $768 \times 512$ pixels. The same original
images will be used to evaluate both the conventional JPEG baseline
and the learned compression model. Using an identical test set makes
the comparison more consistent.

The JPEG baseline is implemented in Python using the Pillow library.
JPEG quality settings are varied to obtain multiple operating points
with different file sizes and reconstruction qualities. For every
compressed image, the actual output file size is recorded. The
compressed file is then decoded, and the reconstructed image is
compared with its original Kodak image.

The current preliminary plots contain five averaged JPEG operating
points. The exact quality settings associated with each point should
be taken from the experiment CSV rather than inferred from the plotted
coordinates. The evaluation script can also be run for the full planned
quality list, if required by the team protocol.

The JPEG results establish a conventional compression baseline. Once
the learned codec is available, it will be evaluated on the same Kodak
images using the same metric definitions.

\section{Proposed Method}
\todo{Student B: Describe the reduced-width hyperprior codec, planned
width or latent-channel settings, and include an architecture figure
or pseudocode. Student A: add any relevant data/training details.}

We plan to use a reduced-width learned image compression model based on
a hyperprior architecture. The encoder transforms an image into a
smaller latent representation, which is quantized for compression. A
hyperprior helps estimate the latent values so they can be encoded
efficiently. The decoder uses the encoded representation to reconstruct
the image. This design follows the general approach of learned
hyperprior codecs \citep{balle2018scalehyperprior}, while drawing on
later work on efficient learned compression \citep{he2022elic}.

The model will use fewer channels than a standard configuration to
keep training manageable with our available compute. The exact channel
widths and training settings will be selected during implementation
and reported with the experiments. We will compare reconstructed
images against the originals using the evaluation pipeline described
above. Where possible, the bitrate will be calculated from the actual
encoded bitstream rather than an estimated target rate.

Figure~\ref{fig:codec-architecture} shows the planned codec
architecture. We will use a reduced-width model to make training more
manageable. The exact channel widths and training settings will be
chosen during implementation. We will first try training on a laptop
and use Google Colab if the laptop’s runtime or memory is not
sufficient.

\section{Evaluation Plan}

The evaluation is designed to compare compression rate, reconstructed
image quality, and decoding performance. Three primary image
compression metrics are used.

\begin{itemize}[leftmargin=*]
    \item \textbf{Bits per pixel (BPP):}
    BPP measures the average number of encoded bits per image pixel.
    For a compressed file with size measured in bytes,
    \[
        \mathrm{BPP} =
        \frac{8 \times \text{compressed file size (bytes)}}
             {\text{image width} \times \text{image height}}.
    \]
    A lower BPP indicates a smaller encoded representation.

    \item \textbf{Peak signal-to-noise ratio (PSNR):}
    PSNR measures pixel-level reconstruction error and is reported
    in decibels (dB). For images represented with a maximum possible
    pixel value $MAX$, it is calculated from the mean squared error:
    \[
        \mathrm{PSNR} =
        10\log_{10}\left(\frac{MAX^2}{\mathrm{MSE}}\right).
    \]
    Higher PSNR generally indicates lower reconstruction error.

    \item \textbf{Multi-scale structural similarity (MS-SSIM):}
    MS-SSIM compares structural information at multiple image scales.
    Its commonly used range is 0 to 1, with values closer to 1
    indicating greater structural similarity.
\end{itemize}

For each JPEG operating point, BPP, PSNR, and MS-SSIM are calculated
for the Kodak images. The per-image measurements are retained, and
the average metric values are used to produce the summary plots.
BPP is calculated from the actual compressed file size, rather than
from an estimated entropy or target bitrate.

Two rate--distortion plots are generated:
\begin{itemize}[leftmargin=*]
    \item Average PSNR (dB) versus BPP.
    \item Average MS-SSIM versus BPP.
\end{itemize}

The same evaluation procedure will be applied to the learned codec.
The comparison will use the same original Kodak images, image
dimensions, color handling, and metric definitions. The final report
will include the individual measurements where appropriate, averages,
and rate--distortion curves. Decoding time will also be measured on
the same hardware environment for both methods. Timing will use
warm-up runs and repeated measurements; file reading time should be
excluded where practical so that the measurement focuses on decoding.

\subsection{Preliminary JPEG Baseline Results}

The first evaluation experiment establishes the JPEG baseline on the
Kodak dataset. The current plots show five operating points, with
average BPP values spanning approximately 0.33 to 2.35 bits per pixel.
The values below are approximate readings from the plotted figures;
the experiment CSV should be treated as the authoritative source for
exact numerical results.

Figure~\ref{fig:jpeg-psnr} shows the average PSNR as a function of BPP.
The plotted PSNR increases from approximately 26.7 dB at the lowest
bitrate to approximately 38 dB at the highest bitrate. This illustrates
the expected rate--distortion trade-off: allocating more bits generally
improves reconstruction quality.

Figure~\ref{fig:jpeg-msssim} shows the average MS-SSIM at the same

\subsection{Evaluation Implementation}

The evaluation pipeline is implemented in Python in Google Colab.
The main libraries used are:
\begin{itemize}[leftmargin=*]
    \item \textbf{Pillow (PIL):} JPEG compression and image decoding.
    \item \textbf{NumPy:} Image-array processing and numerical operations.
    \item \textbf{Pandas:} Organizing and exporting per-image and
    averaged experimental results to CSV.
    \item \textbf{Matplotlib:} Generating the rate--distortion plots.
    \item \textbf{scikit-image:} PSNR calculation.
    \item \textbf{pytorch-msssim:} MS-SSIM calculation.
    \item \textbf{PyTorch:} Tensor handling required by the MS-SSIM
    implementation.
\end{itemize}

The pipeline processes the Kodak images at each JPEG quality setting,
saves the compressed outputs, records their file sizes, decodes them,
and calculates the quality metrics against the corresponding original
images. The measurements are saved in CSV format so that plots and
summary tables can be regenerated.

The metric-calculation functions are kept separate from the codec
implementation. This allows the same evaluation functions to be reused
for the learned compression model and helps maintain a consistent
comparison between JPEG and the learned codec.
